# S2 星穹矿脉新对话交接

更新时间：2026-08-05。

这份文件供下一次 Codex 对话直接接手。开始工作前依次阅读：

1. `DESIGN_INTENT.md`：最高优先级的玩家体验和不可回归约束。
2. 本文件：当前做到哪里、哪些结论有效、下一步做什么。
3. `s2_first_ten_days.py`：当前玩家策略与前期验收入口。
4. `s2_mining_simulator.py`：数值、科技、资源和时代实现。
5. `FIRST_TEN_DAYS_TRACE.md`：固定 seed 的最新操作明细。

`GAME_DESIGN_VNEXT.md` 是完整系统草案，但其中标记为历史基线的数值和日程不能覆盖 `DESIGN_INTENT.md` 与本文件。

## 当前任务边界

- 只设计和验证独立的命令行模拟器。
- 不接主程序、数据库、QQ 指令或正式 HTML UI。
- 不恢复旧 S2 代码，不使用钓鱼主世界货币、药水或成长数据。
- 每轮只解决一个可观察阶段，先打磨前十天，再拼接 D11 以后和重生循环。
- 阶段二的 `10^308` 星球数量外推暂时冻结，阶段一签收后再继续。

## 游戏目标

- 阶段一：挖矿、升级、自动化、跨时代，挖穿一颗星球并重生。
- 重生：清空本地资源与科技，获得星球核心；核心提供永久加速、阶段跳过、更多核心和额外摧毁星球等能力。
- 阶段二：逐渐把单颗星球循环压缩为自动流程，一次摧毁越来越多星球，最终处理近似“无限”的星球数量。
- 最终奖励：宇宙核心，作为返回钓鱼主世界并进入 S3 的钥匙。

理想终值是单星球深度和阶段二星球数都可表达至 `10^308`，但玩家体验优先于强行对齐该数值。通关天数没有硬限制。

## QQ 群核心规则

- 每个自然日最多三条成功的手动升级消息，不限制查看、挖矿结算和状态查询次数。
- 一条升级消息可以包含多个项目和不同数量，例如 `升级 矿镐=2 矿车=1`。
- 任意本地科技累计手动升到 3 级后，永久解锁该科技的自动采购；重生后仍有效。
- 自动采购不消耗 QQ 消息，也不应逐条通知玩家，正式展示按小时或按日聚合。
- 模拟中的活跃玩家每小时检查一次，但只在值得升级时消耗消息。不能把三条消息固定成三个 8 小时窗口。

## 资源职责

- 矿币：通用本地科技货币，由矿物精炼获得。
- 锡矿：基础工程材料。
- 铜矿：工业时代材料。
- 紫晶：电力时代材料。
- 金猫锭：现代与高阶设备材料。
- 虹核晶：未来、行星和异常科技材料。
- 星球核心：重生后的永久科技货币。

这些资源都必须参与成本或转化，不是顶部状态栏的装饰数字。资源种类保持在可理解范围内，不继续无目的扩张。

## 当前模拟状态

当前模型采用 10 分钟固定结算、每 60 分钟玩家检查一次、每天最多三条成功升级消息。时代同时受深度和前一时代科技掌握度限制。

固定 `seed=42`、连续运行 20 天的当前结果：

| 观察点 | 当前结果 |
|---|---|
| D1 第一次升级 | 01:00，矿镐 `+1` |
| D1 手动分布 | `+1×2`、`+2×1`、无 `+3` |
| 工业时代 | D5 首次进入 |
| D10 | 仍处于工业时代 |
| 电力时代 | D13 首次进入 |
| 现代时代 | D19 首次进入 |
| D20 节点覆盖 | 43/124 |

这满足“D1 不空等 8 小时”“D9 进入电力过快”“D10 仍在工业”“电力约 D11～D14”的当前方向。

## 尚未签收的问题

- D4 以后仍频繁出现整条消息直接 `+3`，需要判断是策略过度追求自动化，还是价格与收益过宽松。
- 当前策略常在每天 01:00～03:00 用完三条消息。检查频率正确，但决策价值模型还不够像真人，应该允许为下午新科技或资源门槛保留消息。
- D19 进入现代时代只是当前观测，不是已签收目标；后续时代和首次爆星日期仍需重新校准。
- 旧的 D45 全节点覆盖测试来自更快曲线。减速后如果失败，不要为了保住旧测试而重新加速前十天，应先更新阶段验收顺序。
- 尚未模拟普通玩家每 3 小时检查、低频玩家每天数次检查的差异。

## 当前验证结果

关闭仓库级第三方 pytest 自动加载后，模拟器测试结果为 `7 passed / 3 failed`。失败项是：

这些失败是减速调整后的预期遗留，不是本次文档整理造成的回归。下一次对话应先签收前十天，再决定如何重写长线验收窗口；不要直接删除断言，也不要为让旧测试变绿而提高前期速度。

## 常用命令

从仓库根目录运行前十天回归：

```powershell
.venv\Scripts\python.exe zhenxun/plugins/zhenxun_plugin_fishing/doc/s2设计/星穹矿脉/vnext/s2_first_ten_days.py --days 10 --seed 42
```

运行当前单元测试：

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
.venv\Scripts\python.exe -m pytest zhenxun/plugins/zhenxun_plugin_fishing/doc/s2设计/星穹矿脉/vnext/test_s2_mining_simulator.py -q
```

若 Windows 下 `apply_patch` 报路径或补丁末行错误，阅读插件根目录的 `tools/APPLY_PATCH_WINDOWS.md`。

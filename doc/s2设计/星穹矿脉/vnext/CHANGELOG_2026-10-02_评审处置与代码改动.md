## 零、先回答那个问题：「核心托管」是什么？

它是 **永久科技（星球核心）的自动购买开关**，在页面「PERMANENT TECH / 永久科技」区块的左上角，是一个下拉框，默认 `关闭`。

代码位置：`index.html#coreAutoRoute` → `engine.setCoreAutoRoute(route)` → `engine.autoPurchaseCore()`。

- **它管的是"花核心"，不是"花矿币"**。矿币那条线是「夜班笨助手」（`helperPurchase`）；核心这条线才是「核心托管」。两者完全独立，容易混。
- 选项与实际算法（`coreRouteScore`）：

| 选项 | 行为 |
|---|---|
| `关闭` | 永久科技只能手动点，核心会一直攒着 |
| `均衡低价` | 永远先买当前**最便宜**的那一项 |
| `速度优先` | 全局倍率 / 银河速度 / 速度强化 这三类**按价格÷4 计分**（等于优先级翻 4 倍），其余按原价比 |
| `重建优先` | 收入强化 / 造价折扣 / 设备强化 优先 |
| `爆发优先` | 大爆发 / 银河速度 / 满级冲深 优先 |

- 两个容易踩的细节：**① 偏好要到第 10 颗星球之后才生效**，之前所有路线都等同于"最低价优先"；**② 它是"存钱等目标"**——核心不够买当前目标时就攒着等，不会改买别的便宜货。

**为什么我在反馈里把它拎出来**：它不是"界面没找到"的问题，而是它**决定了这局能不能通关**。模拟器数据（seed 42，纯托管、不手动买科技）：

| 核心托管 | 400 天后 | 结果 |
|---|---|---|
| `关闭` | 41 颗星球、倍率 ×2.7、192 核心闲置 | **永远通不了关** |
| `速度优先` | 2,728.2 万颗（通关目标） | **D123 通关** |

一个默认关闭的下拉框，开与不开的差距是"能通关"和"不能通关"。本轮**没有**改它的默认值（按你的裁决，开关藏起来不算缺陷），但建议在 QQ 端把它做成一条明确指令并默认开启。

## 二、代码改动明细

### 2.1 开挖之后永不停止（P0-3）

**原因定位**：`app.js / renderStatus()` 里有一行 `if ((s.planetComplete || engine.galaxyComplete()) && timer) stop();`——挖穿瞬间就把计时器杀掉；而 `departButton` 的回调里又有一次 `stop()`，启程后也不会重启。两处叠加 = 启程后时钟永久停摆且无提示。

**改法**：

- 只在**银河目标完成**时停表，其余任何情况都不停；
- 按钮 `#toggleButton`：`连续挖矿` → **`▶ 开始挖矿游戏`**，点下之后变成不可点击的状态灯 `⛏ 矿井运转中（时间持续流动）`；
- 新增 `startMining()`，启程、刷新页面都会把矿井续上（`boot()` 里：存档 `minute > 0` 且未通关则自动开工）。

**复验**（浏览器实跑）：挖穿等待启程时 `D31 01:50 → D31 02:50` 仍在走；启程后 `D31 03:00 → D31 03:50` 仍在走。

### 2.2 前 5 次启程必须手动 + 每次挖穿都播报（P0-4）

- `rules.manualDepartures = 5`；引擎新增 `manualDepartureQuota()` / `autoDepartReady()`，`advanceVoyages` / `settleVoyages` / `mineBlock` 里**所有**自动启程分支一律改走 `autoDepartReady()`——批量结算路径同样受限，不会偷偷跳过前 5 次。
- ⚠️ 这里我第一版改漏了一处：`mineBlock()` 里还留着 `s.resets > 0 && s.autoDepart`，于是**第 1 颗星球会乖乖等你点，第 2–5 颗却自己跑了**。是后来补跑仓库自带回归套件、并为这条规则补了一个专门用例才抓出来的（见第五节）。现已修复并在浏览器端逐颗复验。
- 界面提示：「前 5 次启程都要你亲手点（已完成 0/5）——每一次挖穿都值得你亲眼看一下。第 6 次起才会自动。」
- 新增 `announceMilestones()`：**每次挖穿**（含批量，如"本次挖穿 3 颗，累计 14 颗"）、**每个星区完成**、**每批新科技解锁**都会弹出可堆叠的提示条。

### 2.3 删除【完成调试】，术语白话化（P0-5 / P1-8）

- 模板里的 `.commission-button` 整个删除，只留 `亲手建设 +1 级`；
- 「调试 1 / 3」→「**亲手建设 1 / 3**」；「调试门槛 3级」→「**转自动所需 亲手 3 级**（每挖穿一颗少 1 级）」；
- 卡片提示改为「再亲手建 N 级，这台设备就会转给矿井自动升级」。

### 2.4 一键建设改"笨"（P1-6）

```js
// 「一键建设」= 和夜班笨助手同一套笨办法：从最便宜的开始买，一直买到钱不够为止。
// 它不聪明、也不会留钱做规划——省力就不该同时拿到最优解。
for (let guard = 0; guard < 5000; guard += 1) {
  const key = copy.chooseUpgrade("cheapest");
  if (!key) break;
  ...
}
```
去掉了原来的 `batchCommandMaxLevels`（100 级）上限与路线选择。

### 2.5 清单文案（P1-5）

> 这一笔会**花掉 876 矿币**（现有 1,097.23，买完还剩 221.23），共 2 级。
> 买完后产能变化：**矿币收益** +58.76%，**挖矿深度** +58.76%。　本次买不起：**分岔矿道**（还差 538.77 矿币）。

## 三、二阶段重做：7 个星区 + 一路解锁到最后（P1-2 / P1-9）

### 3.1 问题的量化

旧版最后一次永久科技解锁在 **第 300 颗星球**（约 D73），而通关要 649.3 万颗（约 D108）。也就是说**最后 35 天没有任何新内容**，只有数字在涨。更糟的是压轴科技「大爆发」的解锁条件写的是 `unlockResets: 1000100000`（10 亿颗），**超过通关目标本身，等于永久死内容**。

### 3.2 现在的结构

科技从 50 项增加到 **72 项**，解锁点从"1→300 颗"一路铺到"1→1,800 万颗"：

| 星区 | 目标颗数 | 完成奖励 | 基线到达日 |
|---|---|---|---|
| 1 启明星区 | **5** | +3 核心（不代买科技） | D61 |
| 2 猎户支臂 | 12 | +12 核心 ·【银河远航引擎】 | D71 |
| 3 英仙旋臂 | 150 | +260 核心 ·【光帆牵引】 | D81 |
| 4 人马旋臂 | 2.3 万 | +350 万核心 ·【时空锚点】 | D92 |
| 5 盾牌–半人马臂 | 96 万 | +50 亿核心 ·【热寂回收厂】 | D101 |
| 6 银心悬臂 | 440 万 | +1000 亿核心 ·【大爆发】 | D110 |
| 7 银河中枢 | **2,728.2 万（新通关目标）** | — | **D123** |

新增的二阶段科技（解锁颗数）：克尔引力牵引(390) / 超弦编织厂(620) / 零点能抽取(930) / 引力透镜矿场(1,400) / 戴森球群(2,300) / 曲率泡航道(3,600) / 量子退火调度(5,800) / 费米解答(9,600) / 时空锚点(1.6 万) / 熵减引擎(3.3 万) / 银河环流泵(6.1 万) / 暗物质网格(10 万) / 轮回算法(17 万) / 宇宙弦采掘(28 万) / 创世代码(56 万) / 热寂回收厂(96 万) / 多元宇宙枢纽(160 万) / **大爆发(230 万)** / 终焉观测者(280 万) / 宇宙微波回响(490 万) / 克莱因银河(790 万) / 最后的质子(1,200 万) / **万物终章(1,800 万)**。

> **克尔引力牵引**：利用克尔黑洞的拖曳效应牵引矿船。每级令**矿币收益**和**挖矿深度**同时乘以约 ×1.008，满 5 级合计约 ×1.042。空矿井也生效，本地科技仍需从零付费建设。换星保留。

### 3.3 新的通关目标怎么定的（不是拍脑袋）

仓库里本来就有一个标定器 `s2_galaxy_replay.mjs --calibrate`，它的定义就是你说的那条规则：**科技全部研究完成之后，再留 5 天的纯数字墙**。流程是：

1. 把目标临时放大到 1 亿颗跑完整曲线，记下"最后一项科技研究完成"的时刻；
2. 用终局的每颗耗时（`finalSeconds ≈ 0.0465 秒/颗`）折算 5 天的产量；
3. 相加后按 1000 取整 → **推荐目标**。

```
researchComplete : 1,800 万颗 / D115.6   （参考档：每天上线一次 + 均衡低价）
finalSeconds     : 0.0465 秒/颗
requestedTailDays: 5
recommendedTarget: 27,282,000   → 实际尾段 5.0001 天
```

于是 `galaxyTargetPlanets = 27,282,000`。回归测试 `s2_voyage.test.mjs #22` 会在每次改数值后重算这个不变量，手填的目标一定会被它抓住（我第一版手填的 5,000 万就是这么被打回来的）。

**实测通关日**：

| 画像（seed 42） | 通关 |
|---|---|
| 每天上线一次 + 均衡低价 | **D120.6** |
| 全程托管 + 速度优先 | **D122.2** |
| 全程托管 + 均衡低价 | **D125.6** |
| 浏览器实跑（每天看一眼、0 次手动操作） | **D127** |

落在你说的"120 天左右"区间内。

### 3.4 一阶段 / 二阶段的比例

你说的设计意图是两阶段各占一半。重排后实测（托管基线）：

| 阶段 | 内容 | 天数 | 占比 |
|---|---|---|---|
| 一阶段 | 星区 1–2：一颗一颗挖，共 12 颗 | D1–D71 | **58%** |
| 二阶段 | 星区 3–7：批量挖爆星系，到 2,728.2 万颗 | D71–D123 | **42%** |

游戏时间过半（第 62 天）时玩家手里只有 **5 颗**星球——前半程确实是"一颗颗挖穿星球"，后半程才是"挖爆星系"。

"更长的二阶段"和"总时长 120 天"是互斥的：二阶段每多 900 万颗就多 5 天。我按"120 天左右可接受"这句优先，把比例停在 58/42；如果你更看重严格的一半一半，把最后一项科技的解锁点从 1,800 万往上调即可（3,600 万 → 总时长约 140 天，比例 50/50），一行数据的事。

### 3.5 存档对账的坑（实现备注）

`engine.restore()` 里有一条硬校验：`state.cores + 已花费 === 理论产出核心`。星区奖励会凭空增加核心，直接发会让**所有旧存档校验失败**。处理方式：

1. 新增 `sectorBonusCores(completed)`，把已跨越星区的奖励计入"理论产出"；
2. 星区附赠的科技**不是白给等级**，而是先发奖励核心、再走正规 `purchaseCore()` 扣费——这样恒等式仍然成立；
3. `planetsUntilCorePurchase()` 增加星区边界夹取，**批量结算不会一次跨过星区分界**，奖励不会被跳过。

## 四、给"反复试玩这个 demo 的 AI"做的两件事

你提到页面可能有大量样式代码挤占上下文、导致看不到按钮。实际盘下来：

## 八、二阶段：从"五路线下拉"改成"亲手三级后转自动"

### 8.1 旧设计错在哪

二阶段原本是一个和一阶段完全不同的东西：一个 `核心托管` 下拉（关闭 / 均衡 / 速度 / 重建 / 爆发），选了就全自动、不选就全手动。玩家要先理解"路线"这个只在这里出现一次的概念，而且**默认关闭 = 默认通不了关**。

### 8.2 现在的规则（与一阶段逐项对齐）

| | 一阶段（本地设备） | 二阶段（永久科技） |
|---|---|---|
| 手动门槛 | 每项**亲手买 3 级**后转入自动线 | 同左（`prestige.coreCommissionLevels = 3`） |
| 自动线 | 每小时一次，低价优先 | 每颗星球结算后触发，低价优先 |
| 助手 | 笨助手（每天 24:00，尽量买满） | **夜班助手**，同样每天 24:00、尽量买满 |
| 助手默认 | 开 | **开**（独立开关 `coreHelperEnabled`） |
| 助手买到的级数 | 计入"助手"而不是"亲手" | 同左；它**也会替你凑那前 3 级** |

存档字段：删除 `coreAutoRoute`，新增 `coreManualLevels`（每项亲手了几级）、`coreAutoUnlocked`（已转自动的科技）、`coreHelperEnabled`。`restore()` 会校验三者自洽（亲手级数 ≤ min(3, 总级数)、亲手满 3 级 ⟺ 在自动线上），任何一处对不上就整份拒绝。

UI：科技卡现在写「Lv.1/8 · 亲手 1/3 · …… · 还差 2 星球核心」，买完第 3 级会播报"已转入自动线"；开关下方常驻一行提示「x/72 项已转自动」。

### 8.3 科技体系跟着改了什么

**只改了必须改的，没有为了"适配自动线"去动你已经认可的数值。** 具体说：我一度把 6 项 `maxLevel = 3` 的压轴科技（行星解体工程、永恒城、真空衰变、时冕、热寂回收厂、大爆发）提到 5 级、把每级效果按比例缩小，想让它们也能经历"3 级手动 + 2 级自动"的完整流程。跑回归时 `voyage #15 / #17` 立刻报错——那两条用例里写死的是**设计意图数值**（终局倍率、每级增益）。于是全部还原：

> `maxLevel = 3` 恰好等于转自动门槛，意味着这 6 项压轴科技天生就是"全程亲手（或夜班助手代买）"，不需要为了适配自动线而改级数。这是规则的自然结果，不是遗漏。

通关目标用 `--calibrate` 重新标定过：仍然是 **27,282,000 颗**（研究在 1800 万颗 / D115.6 完成，终局 0.04654 秒/颗，尾段 5.0001 天），所以 `galaxyTargetPlanets` 一个字没改，`voyage #22` 的不变量继续成立。

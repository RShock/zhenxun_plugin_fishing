# S2 星穹矿脉 vNext 设计意图与验收约束

本文件是助手版 schema v3 的现行要求，取代历史方案中“一条命令只能升一级、每天必须 3-6 级”的解释。用户已明确允许批量与托管，核心约束是操作不失控、每天上线一次也能推进。

## 1. 产品边界

- S2 是独立增量玩法，不继承钓鱼主世界货币、药水或能力。
- 当前只修改 `vnext` 模拟器、共享数据、独立网页和文档；不接 NoneBot、数据库或正式入口。
- 首星以未来时代收尾，不锁定 30 天或两个月。终点深度标定为 `2.4e19`；挖穿后获得星球核心，下一颗星全部本地建设重置，而非保留满级设备。
- 当前实现首星、核心科技、连续转生与银河终局原型，保持已认可的 D1-D30 经济。终点由全部科技完成后约五天产能反推，不限定百万；科技变更后重新标定。自然开局回放和后期批量结算分别验收；长线节奏仍为草案，不支持超出双精度范围的大数，不接正式奖励发放。
- Python 测试与网页必须读取同一份版本化游戏定义，并用固定 seed 对拍。

## 2. 升级守恒与操作语义

- 一次命令可购买同科技多级或多个科技。购买等级数、命令数、访问次数不得混算。
- 请求全部合法后依序执行；遇到第一个不可购买等级停止，保留已完成等级。无成功购买不计命令；至少成功一级只计一条命令。最多 100 级是单请求输入保护，不是每日配额。
- 网页批量建设使用副本预览，确认前不改变真实存档；单项可升一级或一次完成剩余调试。
- 本星调试门槛为 `max(0, 3 - 转生次数)`，玩家和助手的调试均有效；`manualLevels` 是兼容旧命名。换星时调试记录清空，门槛下降才是永久能力。
- 科技数量不能再用“总天数×点击次数”倒推。可以有 200 项科技，以时代与设备换代充实内容；不同科技可以沿用相似升级逻辑，不要求每项发明新机制。
- 自动化不是免费升级。自动采购仍支付矿币，并且必须先为未来最便宜的 3 个真实手动等级保留预算。
- 首星自动采购是每 60 分钟最多 1 级的全局队列。仍需调试的后续星球每 10 分钟最多 `ceil(永久速度倍率)` 级，上限是全科技等级总量。第三次启程后零调试门槛改为连续事件制，资金与前置条件满足就按低价优先真实付费，不再受十分钟时间格限制；未付款的科技不计入自动线。

## 3. 笨助手与经济审计

- 默认开启助手，每个模拟日 00:00 将现有矿币用于最便宜的可购调试等级，直到没有可购项；同价按共享优先序选择。只调试未自动化科技，不参加自动线后续等级采购。
- 助手照价支付，不保留预算、不消耗额外随机数。每日无论开关状态都生成报告；关闭期间不购买，恢复只等下一次午夜、不追补错过的班次。
- 同一时点顺序固定：采矿结算、日期同步、通关检查及核心托管、自动采购、午夜助手、可选换星。首星保持小时采购；仍需调试时逐块采购。完全自动化后按真实采购/解锁/完成事件积分；跨多天推进须与分段推进等价，不能先灌满离线总收入再采购。
- 玩家可随时提前建设或选择路线。助手的不足是时机和顺序，不是隐藏收益惩罚；生产本身不依赖上线。
- 每日 3-6 级只是参考，忘记上线后更多、助手接手后更少都合理。每次访问要真实买到买不起，而不是只准买一级来制造低操作统计。
- 每日一次画像在 20:00 操作；全程托管画像没有手动操作。另保留每日 47/9/5 次查看的压力画像，但不再将其称为每天一次。
- 单日超过 30 个手动调试等级触发诊断预警，低于它不自动代表玩法合格。应同时看等待空档、手动收益和托管时代到达日；四条启发式路线不构成穷尽所有策略的证明。
- 不设每日硬上限、签到收益锁或人工作业冷却。D1 首项升级可负担时间仍应为 30-90 分钟，即使每日画像选择晚些采购。

## 4. 资源约束

- 当前只有一种本地资源：`credits / 矿币`。
- 所有采矿收入直接结算为矿币；D1-D30 不模拟锡矿、铜矿、紫晶、金猫锭或虹核晶。
- 额外收入乘区只影响矿币，不影响深度；额外深度乘区只影响深度，不影响矿币。
- 第二种资源为 `cores / 星球核心`，只在挖穿星球时奖励一次。10 项永久科技共82级，共用核心，不增加第二层的第二种货币或第三次重置。用价格梯度和作用阶段形成取舍，不靠转生次数直接赠送倍率。

## 5. 乘区原则

升级效果大多按等级线性增长，再把不同区域相乘。这样可以通过多个清晰乘号逼近巨大深度，而不要求单项科技自身指数膨胀。

- `挖矿速度` 是唯一按级复乘的普通区域，例如 `1.18^等级`。
- 前十天区域：挖矿速度、并行开采效率、猫矿工产能、额外深度、暴击率/伤害、额外收入、猫群协同、矿石脆弱度、矿镐锐利度、齐心协力、钻进动量、科技共振、班次接力。
- D11-D30 只补入既有过量穿透，其他设备复用已有速度、并行、收入、深度、锐利度等效果；删除压力、矿网、热回收、工艺多样性、级联、弱点、压缩、透镜的活动公式。当前 15 个活动乘区、2 个行星储备乘区。
- 同乘区新旧设备的线性贡献相加，速度设备分别复乘。新设备系数应抵消旧设备累积贡献的稀释，使换代有可见收益；不通过增加联动分母、深度反馈或额外公式制造内容量。
- 储备项可以删除或延期，但新增乘区必须先进入共享数据并说明作用域、公式与解锁阶段。
- `一鼓作气` 是挖穿首颗星球后的后期升级，不得进入 D1-D10。
- 当前旧设备到本代等级上限后不再采购，但既有贡献保留；下一时代以同主题的新设备提供更强效果、新调试阶段与自动线。未来时代可考虑重新开放旧设备上限，但必须另行标定新等级的价格与收益，本版尚未扩级。
- 暴击期望为 `1 + min(0.65, 暴击率) × (1 + 额外暴击伤害)`；不能让先解锁的暴击率在获得伤害科技前完全无效。
- 已知早期限制：两项暴击率设备满级合计 0.72，超过 0.65 封顶，末级可能没有边际收益。本轮为保持前十天基线不改此规则，也不引入溢出暴击联动补偿；新增 D11+ 科技另做逐级有效性测试。

## 6. 时代节奏

- 原始、工业、电气、计算机、未来时代依次展开，主题从手工矿镐、炸药转向电动设备、数控与量子设备；时代进入日允许因操作时机不同而变化。
- D10 每日一次及全程托管画像均应进入电气时代，不应进入计算机时代。
- 固定 seed=42、每日 20:00 的参考里程碑为 D15 计算机、D22 未来；不是强制日期门槛。全托管须在 D30 前进入未来；D11 后首次购买不同科技的最长空档以 72 小时为诊断上限，包含时段边界与末尾。
- D11-D30 在五 seed/四路线每个结算点购买的压力测试中，单日手动调试应不超过 12 级；这是当前版本回归验收线，不是运行时限购规则。
- 时代解锁同时要求深度与上一时代自动化科技数量，不能只靠单一速度线冲过。
- `reserve` 科技只留在共享数据，不进入玩家建设列表或机会搜索；“待发现”只展示实际开放但尚未达到条件的工程。当前共 43 项活动科技、3 项行星储备。
- `calibrate_thirty_days.mjs` 在作者侧按目标时段拟合固定价格与深度，只有显式 `--write` 才改数据。玩家运行时不按当前收入改价，也不靠日期强制开放；校准轨迹不是验证，必须另跑不同画像、seed 和路线。
- 未来时代持续建设，全部 333 级设备升满后仍有约五天实际采矿。目标深度固定，不强制等够五天，也不把满级作为通关按钮；后续星球可因永久能力足够强而提前挖穿，不必买齐所有本地设备。
- 不为延长时长直接调高旧设备等级上限：早期价格在未来收入下可能过低，新等级会以每小时一级清空并挤占未来设备队列。应先验证等待期内有实际成长、每日一次和全托管均可自然收尾。

## 7. 共享数据与存档

- `web/static/s2-vnext/game_data.json` 是资源、时代、乘区、科技、成本、规则和策略的唯一数据源。
- `game_data.schema.json` 当前为 schema v3；`gameVersion` 为 `s2-vnext-v3-helper-1`。结构不兼容必须提升版本。
- 本次内容版本为 `prestige-3`，`playtestDays=30` 仍代表首段独立回放。十天新增科技仍仅在无内容版本且两份等级表同时缺失时补零；旧版转生字段整体缺失则补初值，更新星球目标但不清空本地进度。`prestige-1/2` 保留核心与研究，新增科技补零，关闭核心托管；不额外扣核心或赠研究。以 `legacyCoreLevels` 保存旧价购买等级，按历史价格核对支出，新购等级按新价支付。等级保留，倍率使用当前数据；不保证旧平衡下的航速不变。新版缺字段或旧版单边缺失视为损坏，迁移不修改输入快照。
- 旧三十天版保留时间、余额、深度、等级、RNG 和采购时钟；超过新终点的旧档在下一次推进时结算一次完成。转生存档校验已挖穿数、转生数、完成标记及核心获得/支出守恒。
- 网页迁移前备份到原键加 `-before-prestige-3`，备份失败只允许临时试玩，不覆盖原件。验收使用 `?sandbox=1` 的独立键，不推进玩家当前矿井。旧百万终点存档在新目标尚未达到时可继续启程。
- 新存档键为 `s2-vnext-save-v3-helper`，不读取套用或删除旧版存档。损坏的新存档先备份，再新开；备份失败则只提供临时进度，不能覆盖原件。
- 网页 RNG 使用 `python-mt19937-v1`，存档同时保存 RNG 状态。
- 助手与自动采购时钟存档，载入后不得重复午夜班次。脚本缓存版本与结构变更同步，避免新 JSON 与旧 JS 混用。
- 当前原型靠按钮或加速连续推进模拟时间；关掉网页后的现实时间尚不自动累计。正式后端须按服务器时区和离线时间补算，但复用相同事件顺序。

## 8. 验证方法

每次调参必须同时完成：

1. 生成 `THIRTY_DAYS_TRACE.md`，记录 D11-D20/D21-D30 窗口、逐日手动/助手/自动等级、时代到达日和首次科技空档；十天历史报告不覆盖。
2. 对 `seed=1、7、42、99、2026` 与 `balanced / cheapest / depth / income` 四条路线按每个 10 分钟结算点做 D1-D30 机会搜索。
3. 检查操作爆发诊断和阶段推进；不把第 7 级判成失败，也不隐藏 0 级或超过 6 级的日期。
4. 回放 daily / absent / active / regular / low 五种画像，增加五 seed/四路线的 daily/absent 检查。
5. 用 `s2_web_parity_runner.mjs` 对拍 Python/JS 的逐日深度、矿币、时代、等级、自动线和手动时间线。
6. 验证午夜顺序、多日/分段等价、关闭/恢复、随机数不偏移、批量部分成交和预览取消、存档恢复，以及桌面/手机布局。
7. 实际网页从新局访问三十天并批量购买至不可买；对照逐级模拟的逐日级数、末值、回放与刷新恢复，命令数可以不同。旧十天存档续跑二十天须与新局跑三十天等价。
8. 旧“D30 爆星/D45 重生”固定日期要求已经废弃；转生须按真实终点测试，不能为旧日期重新加速前十天。另验首星满级后采矿期、核心奖励一次、完整本地重置、3→2→1→0 门槛、自动换星开关、跨星分段与保存恢复。

独立 pytest 必须设置 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`，避免 nonebug 自动夹具要求启动正式机器人；命令见 `README.md`。既有 `asyncio_mode` 配置警告与本原型无关。

## 9. 玩家说明

- 先用开采行为解释效果，再给适用的等级数值；明确影响矿币收益、挖矿深度还是两者，不让玩家从内部公式猜用途。
- 属性与其他科技的引用用 `**名称**` 标记，网页只渲染为加粗文字，不接受 HTML 或任意 Markdown。术语在说明、状态与工程数据中保持一致。
- “作业面”改称“并行开采效率”，解释为同时在更多矿道开挖。同类倍率相加写成“倍率 +数值”，不能写成总收益每级增加同样百分比；速度科技才按当前速度逐级复乘。
- 猫群协同依赖猫矿工产能类科技的累计等级，不虚构矿工人数；自动线联动可作用于全部产能，不得误写成只增强已自动设备或加快采购。
- 时间效果使用游戏内时间口径，不暗示当前原型已实现现实关页期间补算。深度专属升级明确不增加矿币收益，收入专属升级明确不增加挖矿深度。
- 本地科技卡显示基础系数和当前永久强化倍率；核心研究说明指出强化对象，不把装备系数增加误称为总产能等比例增加。满级、自动化、挖穿三个状态明确区分。
- 全部自动化时显示剩余自动升级等级；全部满级时另行提示，不能用“已交付”把调试结束、设备满级和首星通关混为一谈。

## 10. 转生闭环

- 完成星球后夹紧深度、截断超过终点的当块生产，授予 `1 + floor(本次转生数 / 5)` 个核心，只结算一次。完成期间停止本地采矿与采购，不额外消耗随机数。
- 首次启程由玩家确认；之后默认自动换星，可随时关闭。核心托管默认关闭；可显式选择均衡、速度、重建或爆发。前十颗统一按实际价格启动，此后偏好项按价格除以四排序，其他项按原价；支付仍为原价。先选目标再检查余额，不足就攒核心。启用时和每次获得核心后检查采购；自动换星开关与核心托管相互独立。
- 换星清空矿币、深度、所有本地等级/调试/自动线、已发现工程、本星时代记录、助手报告与本地年龄；保留核心、永久研究、累计审计、设置、全局时间与采购时钟。全满级时间仅作观察，不作解锁门槛。
- 永久速度为 `(1 + 行星开采引擎等级) × 2^(银河远航引擎等级/4)`，只有花核心购买才增加。行星引擎首级花 1 核心获得总倍率 ×2，下一级花 3 核心变成总倍率 ×3（相对提升 50%）。转生次数和未消费的核心余额都不提高产速。
- 行星核心钻头每级强化所有速度设备基础系数30%；核心精炼强化收入/班次接力；地核材料强化深度/穿透；恒星铸造强化除速度和暴击率之外的设备；联合勘探按本星真实自动线提供独立公共倍率；银河引擎每四级合计翻倍基础产能。
- 星际标准化建设让本地价格除以 `1+0.25L`，不改变核心价格、前置与解锁深度。行星解体工程仅在本星全部本地科技满级后将深度乘以 `1+L`，不增加矿币；三档价格2/6/18，定位前中期收尾，避免无收益的高价末级。
- 大爆发只作用于抵达本星前1秒，三档为×34/×67/×100，同时影响矿币和深度；到期立即失效，中途购买不重启计时。连续积分必须在该时间边界拆分，不能将爆发延伸至整个采购事件。短航程可以完全覆盖，长航程收益应很小。
- 永久科技按已完成 1/3/5/10/1000 颗星解锁。数据字段 `unlockResets` 为早期命名，实际门槛是已完成星球数，因此首星奖励可立即用于第一项研究，不必先启程。
- 前三颗星保留原十分钟期望扰动模型。第四颗起采用确定性期望产出，精确积分本星年龄效果；按采购、深度解锁与终点跳跃，最后一段实际生产仍保留，不要求科技全满才通关。
- 相同永久科技及新星起始条件只编译一次完整航程；核心余额和转生数不作为产速参数。手动中途购买核心科技后，从当前余额、深度和设备继续重算，不能重置进度。

# S2 星穹矿脉 vNext 设计意图与验收约束

本文件是助手版 schema v3 的现行要求，取代历史方案中“一条命令只能升一级、每天必须 3-6 级”的解释。用户已明确允许批量与托管，核心约束是操作不失控、每天上线一次也能推进。

## 1. 产品边界

- S2 是独立增量玩法，不继承钓鱼主世界货币、药水或能力。
- 当前只修改 `vnext` 模拟器、共享数据、独立网页和文档；不接 NoneBot、数据库或正式入口。
- 产品目标仍是约两个月挖穿首星，再约两个月完成大量星球；首次通关后才解锁以已完成星球数为核心的第二层资源，大部分首轮建设重置。
- 当前验证扩展至 D1-D30，接续用户认可的前十天，不重做起步节奏。首次爆星、重生、超出双精度范围的大数扩展及 120 天节奏尚未实现或验证，开发用目标深度不是正式首星终点。
- Python 测试与网页必须读取同一份版本化游戏定义，并用固定 seed 对拍。

## 2. 升级守恒与操作语义

- 一次命令可购买同科技多级或多个科技。购买等级数、命令数、访问次数不得混算。
- 请求全部合法后依序执行；遇到第一个不可购买等级停止，保留已完成等级。无成功购买不计命令；至少成功一级只计一条命令。最多 100 级是单请求输入保护，不是每日配额。
- 网页批量建设使用副本预览，确认前不改变真实存档；单项可升一级或一次完成剩余调试。
- 同一科技累计完成 3 个调试等级后永久自动化，玩家和助手的调试均有效；`manualLevels` 是兼容旧命名，实际代表共同调试数。
- 科技数量不能再用“总天数×点击次数”倒推。可以有 200 项科技，但每项应承担阶段、新联动或建设选择，不必把内容数量等同操作负担。
- 自动化不是免费升级。自动采购仍支付矿币，并且必须先为未来最便宜的 3 个真实手动等级保留预算。
- 自动采购是**全局队列**：当前每 60 分钟最多结算 1 级，而不是每条自动线各自每小时购买一级。

## 3. 笨助手与经济审计

- 默认开启助手，每个模拟日 00:00 将现有矿币用于最便宜的可购调试等级，直到没有可购项；同价按共享优先序选择。只调试未自动化科技，不参加自动线后续等级采购。
- 助手照价支付，不保留预算、不消耗额外随机数。每日无论开关状态都生成报告；关闭期间不购买，恢复只等下一次午夜、不追补错过的班次。
- 同一时点顺序固定：采矿结算、日期同步、小时自动采购、午夜助手。跨多天推进必须与逐个 10 分钟推进完全等价，不能把离线总收入先灌满再集中采购。
- 玩家可随时提前建设或选择路线。助手的不足是时机和顺序，不是隐藏收益惩罚；生产本身不依赖上线。
- 每日 3-6 级只是参考，忘记上线后更多、助手接手后更少都合理。每次访问要真实买到买不起，而不是只准买一级来制造低操作统计。
- 每日一次画像在 20:00 操作；全程托管画像没有手动操作。另保留每日 47/9/5 次查看的压力画像，但不再将其称为每天一次。
- 单日超过 30 个手动调试等级触发诊断预警，低于它不自动代表玩法合格。应同时看等待空档、手动收益和托管时代到达日；四条启发式路线不构成穷尽所有策略的证明。
- 不设每日硬上限、签到收益锁或人工作业冷却。D1 首项升级可负担时间仍应为 30-90 分钟，即使每日画像选择晚些采购。

## 4. 资源约束

- 当前只有一种本地资源：`credits / 矿币`。
- 所有采矿收入直接结算为矿币；D1-D30 不模拟锡矿、铜矿、紫晶、金猫锭或虹核晶。
- 额外收入乘区只影响矿币，不影响深度；额外深度乘区只影响深度，不影响矿币。
- 后续允许多种有明确用途的资源与星区，但重生资源只能在首次真正挖穿星球后出现，不能污染当前首星验证。

## 5. 乘区原则

升级效果大多按等级线性增长，再把不同区域相乘。这样可以通过多个清晰乘号逼近巨大深度，而不要求单项科技自身指数膨胀。

- `挖矿速度` 是唯一按级复乘的普通区域，例如 `1.18^等级`。
- 前十天区域：挖矿速度、同时矿脉、猫矿工、额外深度、暴击率/伤害、额外收入、猫群协同、矿石脆弱度、矿镐锐利度、齐心协力、钻进动量、科技共振、班次接力。
- D11-D30 接入过量穿透、地层压力转化、能源级联、热量回收、引力透镜、矿网拓扑、弱点标定、路程压缩、工艺多样性；公式及作用域见 `THIRTY_DAYS_PLAYTEST.md`。
- `cascade` 按时代内自动化比例联动，新增同一时代科技会改变分母；后续加内容前须检查老玩家即时产能，不能只检查新科技的解锁深度。
- 储备项可以删除或延期，但新增乘区必须先进入共享数据并说明作用域、公式与解锁阶段。
- `一鼓作气` 是挖穿首颗星球后的后期升级，不得进入 D1-D10。
- 时代内科技可以设上限；下一时代可出现同主题的新科技，提供新的调试阶段和自动线。
- 暴击期望为 `1 + min(0.65, 暴击率) × (1 + 额外暴击伤害)`；不能让先解锁的暴击率在获得伤害科技前完全无效。

## 6. 时代节奏

- 基础工程、工业协作、电气矿网依次展开；时代进入日允许因查看时机不同而变化，不能把旧版分日标签当 v3 已证明的固定日程。
- D10 每日一次及全程托管画像均应进入电气时代，不应进入现代时代。
- 固定 seed=42、每日 20:00 的参考里程碑为 D15 现代、D22 未来；不是强制日期门槛。全托管须在 D30 前进入未来；D11 后首次购买不同科技的最长空档以 72 小时为诊断上限，包含时段边界与末尾。
- D11-D30 在五 seed/四路线每个结算点购买的压力测试中，单日手动调试应不超过 12 级；这是当前版本回归验收线，不是运行时限购规则。
- 时代解锁同时要求深度与上一时代自动化科技数量，不能只靠单一速度线冲过。
- `reserve` 科技只留在共享数据，不进入玩家建设列表或机会搜索；“待发现”只展示实际开放但尚未达到条件的工程。当前共 43 项活动科技、3 项行星储备。
- `calibrate_thirty_days.mjs` 在作者侧按目标时段拟合固定价格与深度，只有显式 `--write` 才改数据。玩家运行时不按当前收入改价，也不靠日期强制开放；校准轨迹不是验证，必须另跑不同画像、seed 和路线。

## 7. 共享数据与存档

- `web/static/s2-vnext/game_data.json` 是资源、时代、乘区、科技、成本、规则和策略的唯一数据源。
- `game_data.schema.json` 当前为 schema v3；`gameVersion` 为 `s2-vnext-v3-helper-1`。结构不兼容必须提升版本。
- 本次内容版本为 `thirty-day-1`，`playtestDays=30`；十天助手版存档只补新增科技，不重置已有经济。只有缺少 `contentVersion` 且新增 key 在 `levels/manualLevels` 都不存在才可补零；单边缺失或新版缺字段视为损坏。补零不得修改传入快照。
- 网页迁移前备份到原键加 `-before-thirty-day-1`，备份失败只允许临时试玩，不覆盖原件。验收使用 `?sandbox=1` 的独立键，不推进玩家当前矿井。
- 新存档键为 `s2-vnext-save-v3-helper`，不读取套用或删除旧版存档。损坏的新存档先备份，再新开；备份失败则只提供临时进度，不能覆盖原件。
- 网页 RNG 使用 `python-mt19937-v1`，存档同时保存 RNG 状态。
- 助手与自动采购时钟存档，载入后不得重复午夜班次。脚本缓存版本与结构变更同步，避免新 JSON 与旧 JS 混用。
- 当前原型靠按钮或加速连续推进模拟时间；关掉网页后的现实时间尚不自动累计。正式后端须按服务器时区和离线时间补算，但复用相同事件顺序。

## 8. 验证方法

每次调参必须同时完成：

1. 生成 `THIRTY_DAYS_TRACE.md`，记录 D11-D20/D21-D30 窗口、逐日手动/助手/自动等级、时代到达日和首次科技空档；十天历史报告不覆盖。
2. 对 `seed=1、7、42、99、2026` 与 `balanced / cheapest / depth / income` 四条路线按每个 10 分钟结算点做 D1-D30 机会搜索。
3. 检查操作爆发诊断和阶段推进；不把第 7 级判成失败，也不隐藏 0 级或超过 6 级的日期。
4. 回放 daily / absent / active / regular / low 五种画像，增加五 seed/四路线的 daily/absent 检查。
5. 用 `s2_web_parity_runner.mjs` 对拍 Python/JS 的逐日深度、矿币、时代、等级、自动线和手动时间线。
6. 验证午夜顺序、多日/分段等价、关闭/恢复、随机数不偏移、批量部分成交和预览取消、存档恢复，以及桌面/手机布局。
7. 实际网页从新局访问三十天并批量购买至不可买；对照逐级模拟的逐日级数、末值、回放与刷新恢复，命令数可以不同。旧十天存档续跑二十天须与新局跑三十天等价。
8. 旧“D30 爆星/D45 重生”测试仍明确跳过，不能算通过，不能为历史断言重新加速前十天；当前另设三十天建设验收。

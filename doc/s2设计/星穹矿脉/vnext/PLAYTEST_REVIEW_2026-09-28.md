## 一、本次发现并已修复的问题（改动见 git 提交）

### 1.【严重·存档】`structuredClone` 无兜底 + 错误信息误导
- **现象（玩家）**：页面常驻提示"浏览器存储不可用，本次进度未保存"，实际上 localStorage 完全可用。
- **根因（代码）**：`engine.snapshot()` 直接调用 `structuredClone`；该 API 在 Safari < 15.4 与部分 WebView 中不存在，在无头测试环境中同样缺失。`save()` 的 `catch` 把**任何**异常（包括序列化 ReferenceError）一律误报为"浏览器存储不可用"。旧浏览器玩家会**静默丢档**且被错误信息误导。
- **修复**：`engine.js` 新增 `deepClone()`（structuredClone → JSON 兜底），替换全部 3 处调用；`save()` 失败提示带上真实异常信息。
- **验证**：修复后存档正常写入、刷新/重载接续进度，通关状态跨重载保留；全程 console 零报错。

### 2.【严重·UX】打开"批量建设"会静默暂停连续挖矿，关闭后不恢复
- **现象（玩家）**：开着"连续挖矿"点了一下批量建设，游戏时间从此冻结，页面无任何提示（我最初以为游戏挂了）。原版里该路径还会因问题 1 直接崩溃（`previewPlan` 第 2 行 `snapshot()` 抛错），弹窗空白、什么都没发生但时间已停。
- **根因**：`previewPlan()` 第一行无条件 `stop()`；确认/取消/Esc 关闭弹窗后没有任何恢复逻辑。
- **修复**：新增 `pauseForDialog()/maybeResumeMining()`——记录弹窗打开前的推进状态，`planDialog`/`resetDialog` 触发 `close` 事件时自动恢复；弹窗摘要中同步提示"连续挖矿已暂停，关闭本清单后自动继续"。

### 3.【中·UX】NEXT 卡片与 ETA 横幅推荐不同的"下一项"
- **现象（玩家）**：卡片说下一项是 A，横幅说下一项是 B（实测"蒸汽钻列"vs"深层标尺"），两个指示器打架。
- **根因**：卡片取"最便宜可买"，横幅取"3 天内可达、按数据顺序的第一个"，两套口径。
- **修复**：`nextUpgradeEstimate(preferredKey)` 统一口径——默认与卡片一致（最便宜可买项），横幅区分"受深度限制"（显示深度目标）与"受矿币限制"（显示矿币差额）两种文案。
- **验证**：修复后卡片与横幅始终同名。

### 4.【中·UX】助手"建设 0 级"没有任何原因说明
- **现象（玩家）**：D2 首班"建设 0 级 · 本班没有新增建设"，不知道是 bug、是没矿币还是没得买。
- **修复**：`helperPurchase()` 在 0 级时写入 `reason`（值班暂停 / 无满足条件设备 / 矿币不足+最便宜项还差多少），`renderHelper` 与推进提示展示原因；另两处 `lastHelperReport` 构造统一补 `reason: ""` 字段（保持 schema 一致，向后兼容旧存档）。同步更新 `s2_engine.test.mjs` 对应断言。

### 5.【低·UX】禁用按钮无解释
- "批量建设"长期禁用（无可负担工程时）、"推进1秒"在全自动前禁用，均无提示。已补 `title` 悬浮说明。

## 二、确认不是 bug、但值得记录的观察（jsdom 伪影）

- `$(...).close is not a function` / `requestSubmit not implemented`：来自测试环境缺失 `<dialog>` API；真实浏览器正常。驱动器侧以 polyfill 规避（不改游戏代码）。
- "弹窗关不上"：实际是 `previewPlan` 崩溃导致弹窗从未打开（问题 1+2 的组合表现）。

## 三、策划视角：体验与数值观察（未改动，供后续调整）

0. **【复测发现 → 已确认为刻意设计，问题仅剩"无提示"】核心消费是参与门槛**：核心托管默认 `off`，纯挂机玩家（从不购买永久科技）从第 2 颗起进入每颗 ~25 天的固定节奏，银河目标对其不可达——**作者确认这是刻意设计，纯挂机本就不应通关**。真正的问题只是：整个平台期页面从不解释这条规则，玩家不知道"核心必须花掉才变强"。已于第三轮实现 `coreIdleHint`（核心闲置行动提示）补上这块教学：提示只负责让玩家看懂规则并给出两条路径（手动购买 / 开托管），不代做决策、不改变门槛本身。
1. **前 30 分钟是全程最枯燥段**：0→3 级手工矿镐期间玩家几乎无事可做（等 37 分钟 → 点 4 次按钮）。第一批自动线形成（约 D1 内）后体验迅速好转。可考虑开局给 1 级或缩短首项时间。（复测注：纯托管下 D2 助手首班即可买 6 级，首日体验其实成立；枯燥段主要影响"手动精玩"玩家。）
2. **助手的"每日一班"在前 3 天感知很弱**（0-5 级/班），中期存在感最强（8-13 级/班）。节奏可接受。
3. **中后期"推进1天"完全接管**：D54 全自动后，玩家决策只剩"核心托管路线"一个选择，之后纯看数字飞。作为试玩标定工具没问题；作为正式玩法，中后期缺少决策点（50 项永久科技大部分时间在托管下自动买完）。
4. **指数段的呈现**：日挖 120 万颗、每颗 0.07 秒时，"最近航程"列表全是相同行，信息量趋零。可加"稳定态摘要"（如：当前每颗 X 秒 / +Y 核心，Z 天后达成银河目标）。
5. **数字格式**：深度用 `2.40e+19`、核心用"1.28万亿"两种风格混排（`formatNumber` 在 1e15 以上切科学计数法），玩家视角稍显不一致，可统一为中文单位或科学计数法之一。
6. ~~路线选择器只有"均衡建设"一项~~ **已更正（2026-09-28 复核）**：下拉框实际有 4 个选项（均衡/最低价格/深度优先/收入优先），初判"只有一个选项"是试玩工具 UI 转储只列出选中项造成的观察伪影，并非页面问题。
7. **通关时间（快进）**：101 天，其中前 29 天在第一颗星球（28.7%）。若目标含"真实时钟挂机"（连续挖矿约 30 秒/天），单星 29 天 ≈ 15 分钟真实时间，全程约 1 小时——作为附加玩法节奏合理。

## 七、第三轮：QQ 场景玩法优化（按「玩家+策划」结论实施）

> 设计前提（来自产品定位）：本游戏是 **QQ 群机器人玩法**——玩家每天只进行少量交互，
> 且**不能让玩家产生一直盯着的欲望**（会刷屏）。部分等待节奏是刻意设计。
> 以下改动全部在 `app.js` / `index.html` / `style.css`，未触碰 `engine.js` 数值逻辑；资源版本升至 `v3-prestige-5`。

### 令人费解的描述

1. **数字格式统一为中文数量级**：`formatNumber` 改为 万/亿/万亿/亿亿 阶梯（≥1e20 才科学计数法）。
   原先「深度 2.40e+19」与「核心 1.28万亿」混排，群消息里根本没法读；现在目标深度显示为「2,400亿亿」。
2. **银河目标文案去开发腔**：原「试玩终点为…按本轮科技终点后约5天采矿标定；这是可继续调整的试玩目标，不是倒计时」是标定笔记直接漏给了玩家。改为：「**银河目标**：累计挖穿 649.3万 颗星球（已完成 X%）。每挖穿一颗…都会让下一颗更快——按自己的节奏来就好。」
3. **挖穿进度补百分比**：`深度 21.62亿亿 / 2,400亿亿（0.9%）`——「挖穿进度」比裸深度数字更符合玩家心智（≥0.01% 才显示，避免前期 0.0000…%）。

### 困惑的步骤

4. **「调试」术语自解释**：装备建设区新增常驻提示「每台设备手动建设满 3 级（即「完成调试」）后转入自动线，由矿井自动继续升级——不需要一直盯着」；调试进度条与「完成调试」按钮补 title 说明。原先后玩家不明白 0/3 是什么、为什么要建 3 次。
5. **核心闲置行动提示**（纯挂机停滞为刻意门槛，此提示只负责教学——让玩家看懂"核心放着不会自己变强"并给出手动购买/开托管两条路径，不代做决策、不改变门槛）：托管关闭且核心 ≥ 最便宜可购永久科技时，航程面板显示「💡 N 个星球核心闲置中——核心放着不会自己变强。现在就可以购买「行星开采引擎」（1 核心），或在上方「核心托管」选一条路线让矿井自动消费。」实测 D29 首次启程后立即出现，正好接住"第一次拿到核心不知道该干嘛"的玩家。

### 玩家会不满的点（等待是故意的，但要不透明地等）

6. 等待本身保留（QQ 节奏），但把"盲等"变"定点回来看看"，见下。

### 灵光乍现的巧思

7. **「下次看点」**：NEXT 面板新增常驻行 `🕒 下次看点：D1 00:37:30 · 「手工矿镐」可开工 —— 在那之前可以放心离开`；
   取助手值班 / 下一工程可开工 / 下一时代解锁三者最早的时刻（时代与工程标注"按当前产速预计"，两周内才提示避免误导）。
   每次推进摘要末尾也追加一条。这是对"不要让玩家一直看"最直接的回答：**明确告诉玩家可以走了，以及什么时候回来值得**。
8. **时代变迁公告**：推进跨越时代时摘要首部插入「🎉 进入【工业时代】」。时代跃迁是本作最重要的正反馈节点，原先后端变了、前端一声不吭。

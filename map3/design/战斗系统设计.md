## 1. 世界观与玩法定位

老鼠的「工业联合体」在九片海域填海建厂、排污倾海，猫猫远洋舰队从猫港出发，逐个拔除要塞。
玩法是**点击推进的自动战斗航海游戏**：出海 → 航行中随机遭遇 → 抵达目标点 → 要塞攻坚 → 占领后成为新起点。

## 2. 战斗系统

### 2.1 核心循环

- **行动条制**：每个刻度所有单位按速度累积行动条，先到 100 者行动；速度直接换算出手机频率（速度高的单位"多打一轮"）。
- **低数值**：L1 属性 50~80 HP / 8~13 攻击；L20 约 180~250 HP / 22~40 攻击。伤害两位数，便于玩家心算。
- **乘法公式**（标准 RPG，扩展性好）：

```
基础伤害 = ATK × 技能倍率 × 50 / (50 + 防御×(1-穿甲))
最终伤害 = 基础 × 增伤(被动/处决/易伤) × 暴击(默认1.5×) × 随机浮动(0.94~1.06)
```
  - 防御收益递减但不归零（护甲流不会变成无敌）；
  - 只加"乘区"就能扩展新内容（易伤、破甲、处决、属性克制），不会像减法公式那样崩坏。
- **能量**：普攻 +20、受击 +8、上限 100；大招消耗 50（大招1）/ 80（大招2）。
- **暴击**：基础 3%~15%，暴击伤害 1.5×（可被被动提升）。

### 2.2 角色结构（我方与敌方同一套系统）

| 槽位 | 类型 | 解锁等级 |
|---|---|---|
| 被动 1 | 常驻 / 触发 | Lv1 |
| 大招 1 | 主动，50 EN | Lv5 |
| 被动 2 | 常驻 / 触发 | Lv10 |
| 大招 2 | 主动，80 EN | Lv15 |

角色等级上限 20，10 级技能全部解锁，11~20 级继续吃属性成长（成长曲线见下）。
我方最多上阵 4 名，敌人按难度 3~5 名。

### 2.3 成长曲线（20 级）

```
属性(L) = 基础 × (1 + 系数 × (L-1))
HP 10.5%/级 → L20 ≈ ×2.99      ATK 9.0%/级 → ×2.71
DEF 8.5%/级 → ×2.61            SPD 5.0%/级 → ×1.95
暴击 +0.25%/级
```
设计意图：HP/ATK 成长快于 SPD，保证战斗节奏随等级略微拉长（同级战斗 40~60 刻度），不会出现"高级别秒杀"。

### 2.4 状态与关键词

| 关键词 | 效果 |
|---|---|
| 护盾 | 优先吸收伤害，独立存在，按回合递减 |
| 灼烧 / 中毒 | 回合开始按施加者攻击结算的持续伤害（可被"防腐皮"等减免） |
| 引爆 | 消耗目标的灼烧层数造成额外伤害（三花·机械师） |
| 嘲讽 | 强制敌方单体技能指向自己 |
| 晕眩 / 冰冻 | 跳过 1~2 回合行动 |
| 易伤 / 破防 / 降攻 / 降速 | 乘法增减益 |
| 追击 / 散弹 | 普攻后的额外行动或群体化 |
| 处决 | 目标低于阈值时伤害放大 |
| 充能 / 额外行动 | 能量与行动条的资源操作 |

### 2.5 AI 决策

每名单位行动时按「大招 ai.prio」投票，满足条件（如队友血量 <70%、敌人 ≥3、目标有灼烧、回合数 ≤3）才启用；
无条件大招默认不高于普攻优先级。因此 AI 会自然形成"残血奶一口、群怪开群攻、斩杀手盯残血目标"的战术，不需要玩家操作。

### 2.6 平衡旋钮

`M3.tuning.enemyStatScale`（默认 **0.92**）是敌方全属性系数。
它同时是后续"要塞难度 / 杂兵强度"的调节阀：要塞战把系数调到 1.05~1.25 即可拉出攻坚压迫感。

## 4. 平衡验证结果

测试工具：`map3/tools/sim.js`（胜率/节奏/技能使用率）、`map3/tools/report.js`（角色体检）、`map3/tools/matrix.js`（等级压制矩阵，输出 `src/balance-matrix.json`）。

### 4.1 同等级胜率（我方 4 人 等战力编队 vs 同等级鼠群）

| 我方等级 | 敌方 | 胜率 | 剩余血量 | 平均存活 |
|---|---|---|---|---|
| L1 | L1 ×3 | 100% | 83.6% | 3.91/4 |
| L5 | L5 ×4 | 100% | 74.3% | 3.50/4 |
| L10 | L10 ×4 | 100% | 73.1% | 3.46/4 |
| L14 | L14 ×5 | 97.1% | 54.6% | 2.81/4 |
| L15 | L15 ×5 | 99.3% | 58.3% | 2.94/4 |
| L20 | L20 ×5 | 100% | 59.6% | 2.98/4 |

**各档位同级胜率均 ≥97.1%，满足"同级胜率 ≥95%"的要求**（1500 场/档复核：L15 99.0%、L20 99.5%）。
最坏情况（只上 4 名辅助系：塔菲/米娅/阿豹/齿轮，5 鼠）为 97.1%，随机编队 99%+。

### 4.2 等级压制曲线（越级挑战的难度感）

| | 敌 L10 | 敌 L12 | 敌 L14 | 敌 L16 | 敌 L18 | 敌 L20 |
|---|---|---|---|---|---|---|
| 我方 L10 | 100% | 79% | 27% | 4% | 1% | 0% |
| 我方 L15 | 100% | 100% | 100% | 95% | 75% | 32% |

- **越级 2 级 ≈ 八成胜算**（可打但会掉人），**越级 4 级 ≈ 两成**（需要先练级）。
- 由此确定要塞战难度公式：要塞敌方等级 = 地图等级 **+2~+3**，配合 `enemyStatScale` 上浮，前期可打、后期必须练级。
- 消灭杂兵数量差也很关键：4 猫打 5 鼠时胜率会掉约 1~2 个百分点，所以"鼠海"本身就是难度来源。

### 4.3 角色体检（L20，1000 场，纳入率 = 被"势均力敌"选人算法抽中的概率）

| 角色 | 职业 | 纳入率 | 均输出 | 存活率 |
|---|---|---|---|---|
| 银渐·炮术长 | 控制 | 36.7% | 208 | 66.0% |
| 布偶·炮手 | 群攻 | 41.0% | 287 | 60.3% |
| 奶牛·水手长 | 吸血 | 40.5% | 221 | 79.5% |
| 缅因·铁锚 | 破防 | 42.6% | 170 | 77.7% |
| 三花·机械师 | 持续伤害 | 41.2% | 185 | 63.4% |
| 狸花·督头 | 指挥 | 40.2% | 172 | 65.6% |
| 暹罗·斥候 | 连击 | 41.6% | 342 | 71.9% |
| 橘座·舰长 / 白爪·医官 / 黑尾·夜刃 | 守护/治疗/爆发 | 37~40% | — | — |

- 10 名角色纳入率 36.7%~42.6%，**没有"废角"也没有"必选角"**，随机编队体验均匀。
- 输出榜符合定位：连击/群攻> DOT/指挥/破防；奶妈与坦克的价值体现在存活率与剩余血量（全辅助阵容剩余血量最高但输出最低，属于正确的取舍）。
- 大招占比 2%~6%：一场战斗约 50 个行动、每名角色 1~2 次大招，符合"大招是节奏点而非刷屏"的预期。

### 4.4 趣味性观察

- 影爪的处决、齿轮的引爆、大副的碎甲都形成了"铺垫→兑现"的连招感；
- 米娅的减伤+回血让"多活两回合"直接转化为胜率，奶妈存在感明确；
- 敌方 10 鼠各有专属机制（反击/麻痹/灼烧/毒/嘲讽/自损），同一等级下每场遭遇战的体验不同；
- 风险点：五鼠 AoE 阵容（烟囱鼠+污水鼠+火药鼠）会同时压全队血线，是唯一能翻盘的组合——已保留为"高危但可控"的随机性。

## 5. 交付物与目录

```
map3/
├── index.html                 模块化页面（引用 src/*.js）
├── simulator.html            单文件版（内联全部代码，离线 / 沙箱预览用）
├── src/
│   ├── data.js               10 猫 + 10 鼠、成长曲线、地图表
│   ├── engine.js             战斗引擎（行动条/伤害/状态/AI/编队算法）
│   ├── ui.js                 页面逻辑（编队、回放、批量模拟、预计胜率）

├── tools/
│   ├── sim.js                胜率与节奏模拟（CLI）
│   ├── report.js             角色体检（纳入率/输出/存活/胜率）
│   ├── matrix.js             生成平衡矩阵
│   └── build.js              生成单文件 simulator.html
└── design/战斗系统设计.md      本文档
```

复现平衡数据：

```bash
cd map3
node tools/sim.js --n=1500 --levels=1,5,10,15,20     # 胜率与节奏
node tools/sim.js --n=1500 --random                  # 最坏情况（随机编队）
node tools/report.js 20 1000                         # 角色体检
node tools/matrix.js 140                             # 刷新等级压制矩阵
node tools/build.js                                  # 重新生成单文件版
```

### 6.1 补给系统接口方案（下一步实现，本期未落地）

**规则**（对应需求原文）：

- 每次出海消耗补给：终点越远，基础补给消耗越高（`补给 = 5 + 4 × 航段距离`，单位"粮箱"）。
- 生活系船员（采集/加工/畜牧等）**可无限携带、几乎不占补给**（每人 +0.2），且能在航行中把渔获转成补给。
- 战斗系船员按"吨位"占用补给：轻装 1 / 中装 2 / 重装 3（与角色 4 槽技能组的强度正相关，越强的猫吃越多）。
- 失败（或中途退出）时按已航行比例扣除补给，避免"无脑送死刷随机"。

**数据结构预留**：

```js
// 角色新增字段（不改动现有战斗字段）
{ id:'cat_mia', role:'治疗', tier:2 /* 1/2/3 补给占用 */, life:false }
{ id:'life_chef', role:'生活', life:true, supplyBonus:0.2 }

// 地图表新增航段消耗
{ id:2, name:'锈齿浅滩', level:3, supplyCost:9, reward:{ supply:6, gold:120 } }

// 出征结算（纯函数，便于单测）
M3.supplyCost = (fromMap, toMap, team) =>
   5 + 4 * (toMap - fromMap)
   + team.filter(c => !c.life).reduce((s, c) => s + c.tier, 0)
   - team.filter(c => c.life).reduce((s, c) => s + c.supplyBonus, 0);
```

**衔接点**：`M3.rollEnemyTeam((fromLevel + toLevel) / 2, 数量)` 已可直接用于航行遭遇战；要塞攻坚时把 `M3.tuning.enemyStatScale` 调到 1.05~1.25 并叠加地图等级 +2~+3 即为要塞难度。
